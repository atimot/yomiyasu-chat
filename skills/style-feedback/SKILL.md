# style-feedback

読みにくい応答を1件ずつ取り込み、yomiyasu-chatの文体を育てる。1回の呼び出しで扱うのは1件。

## 置き場

- データ置き場: `${CLAUDE_PLUGIN_DATA}`。この値が展開されず `${` で始まったままなら `~/.claude/yomiyasu-chat/` を使う
- 台帳: `<データ置き場>/cases.md`
- 個人パターン: `<データ置き場>/patterns.tsv`。タブ区切りで `正規表現<TAB>説明`。`#` 始まりはコメント。Stop hookが次の応答から検出する
- 育てるルール: `~/.claude/rules/yomiyasu-chat.md`。ユーザー単位のrulesとして、全プロジェクトで次のセッション（`/clear` 後）から反映される。無ければ下の雛形で作る
- output style本体（`output-styles/yomiyasu-chat.md`）は変更しない。変更してもプラグインの更新で上書きされるため、原則に関わる変更は追記案を示すだけにし、リポジトリ側で直してもらう

## 手順

対象: $ARGUMENTS。空なら直前の自分の応答を対象にし、どの文が読みにくかったか、何が嫌だったかを1問だけ聞く。

1. 台帳に1件追加する。形式は下の通り。分類は「語彙」「構造」「態度」「装飾」のどれか
2. 嫌だった点が特定の語や言い回しなら、patterns.tsvに1行足す。正規表現は助詞や活用まで含めて狭く書き、過検出を避ける。既存行と重複しないか確認する
3. 台帳に同じ分類で同じ型の事例が既に1件以上あれば、ルールファイルの「NG → OK」に1行足す。初回の事例は、ルールを増やしすぎないためルール化しない
4. 嫌だった点が原則（結論の位置、箇条書きの使い方など）に関わり、output styleの文面を変えるべきなら、追記案を1行示す。ファイルは変えない
5. ルールファイルが80行を超えていたら、統合できる行を提案する。勝手に消さない
6. 変更したファイルと差分を示して終わる。応答は短くする

## 台帳の形式

```markdown
## YYYY-MM-DD / 分類: 構造
- 元の文: （応答の文をそのまま）
- 何が嫌か: （ユーザーの言葉で）
- 書き直し: （こう書けばよかった）
- 対応: patternsに追加 / ルールに追加 / 台帳のみ
```

## ルールファイルの雛形

```markdown
# yomiyasu-chat: 育てる文体ルール

yomiyasu-chatのoutput styleを補う個人のNG → OK集。/yomiyasu-chat:style-feedbackが追記する。

## NG → OK
```

## patterns.tsvの例

