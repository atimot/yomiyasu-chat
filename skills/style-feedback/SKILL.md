# style-feedback

読みにくい応答を 1 件ずつ取り込み、yomiyasu-chat の文体を育てる。1 回の呼び出しで扱うのは 1 件。

## 置き場

- データ置き場: `${CLAUDE_PLUGIN_DATA}`。この値が `${` のまま展開されていなければ `~/.claude/yomiyasu-chat/` を使う
- 台帳: `<データ置き場>/cases.md`
- 個人パターン: `<データ置き場>/patterns.tsv`。タブ区切りで `正規表現<TAB>説明`。`#` 始まりはコメント。Stop hook が次の応答から検出する
- 育てるルール: `~/.claude/rules/yomiyasu-chat.md`。ユーザー rules として全プロジェクトで次のセッション (`/clear` 後) から効く。無ければ下の雛形で作る
- Output Style 本体 (`output-styles/yomiyasu-chat.md`) は変更しない。プラグインの更新で消えるため、原則に関わる変更は追記案を示すだけにし、リポジトリ側で直してもらう

## 手順

対象: $ARGUMENTS。空なら直前の自分の応答を対象にし、どの文が読みにくかったか、何が嫌だったかを 1 問だけ聞く。

1. 台帳に 1 件追加する。形式は下の通り。分類は 語彙 / 構造 / 態度 / 装飾 のどれか
2. 嫌だった点が特定の語や言い回しなら、patterns.tsv に 1 行足す。正規表現は助詞や活用まで含めて狭く書き、過検出を避ける。既存行と重複しないか確認する
3. 台帳に同じ分類で同じ型の事例が既に 1 件以上あれば、ルールファイルの「NG → OK」に 1 行足す。初回の事例はルール化しない。ルールを太らせないため
4. 嫌だった点が原則 (結論の位置、箇条書きの使い方など) に関わり、Output Style の文面を変えるべきなら、追記案を 1 行示す。ファイルは変えない
5. ルールファイルが 80 行を超えていたら、統合できる行を提案する。勝手に消さない
6. 変更したファイルと差分を示して終わる。応答は短くする

## 台帳の形式

```markdown
## YYYY-MM-DD / 分類: 構造
- 元の文: (応答の文をそのまま)
- 何が嫌か: (ユーザーの言葉で)
- 書き直し: (こう書けばよかった)
- 対応: patterns に追加 / ルールに追加 / 台帳のみ
```

## ルールファイルの雛形

```markdown
# yomiyasu-chat: 育てる文体ルール

yomiyasu-chat の Output Style を補う個人の NG → OK 集。/yomiyasu-chat:style-feedback が追記する。

## NG → OK
```

## patterns.tsv の例

```text
# 正規表現<TAB>説明
することが可能です	「できます」と書く
を実現(し|します|できます)	何をどうするかを動詞で書く
```
